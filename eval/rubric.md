# 面试助手回答评分标准（Rubric）

用途：**人工打分与 LLM 裁判共用同一把尺子**，保证不同时间、不同评审者打出的分可比。

## 维度与权重

| 维度 | key | 权重 | 1 分 | 3 分 | 5 分 |
|---|---|---|---|---|---|
| 相关性 | `relevance` | 0.30 | 答非所问 / 跑题 | 部分相关，漏关键点 | 直接答到点，覆盖关键点 |
| 事实性 | `factuality` | 0.35 | 明显编造经历 / 数据 | 泛泛而谈但无明显硬伤 | 无编造，表述有依据、合理 |
| 口语化 | `spoken_style` | 0.15 | 像文档 / 念稿 / 堆术语 | 基本能念出来 | 自然口语，有过渡，能直接说 |
| 长度 | `length` | 0.10 | 过长(>8 句) 或 敷衍(1 句) | 偏长 / 偏短 | 3–5 句，约 30–60 秒 |
| 追问连贯 | `followup` | 0.10 | 没接上文 | 部分接上 | 自然承接上一轮 |

## 硬性规则

- 出现**无依据的具体数字 / 公司 / 项目 / 指标** → 事实性 ≤ 2。
- 提到简历以外、且无法从常识推导的经历 → 事实性 ≤ 2，并标记。
- 只有空泛套话、没有可执行内容 → 相关性 ≤ 2。
- **不要因为回答长就给高分。**

## 通过线

- `overall ≥ 3.5` **且** `factuality ≥ 3` 视为通过。
- 单轮题「追问连贯」记 **N/A**，不计入加权（权重重新归一化）。

## 加权公式

```
overall = Σ(score_i × weight_i) / Σ(weight_i)
```

只统计**已打分**的维度；未打分的维度不参与。

## 输出格式（LLM 裁判）

```json
{
  "relevance":    {"score": 4, "reason": "..."},
  "factuality":   {"score": 5, "reason": "..."},
  "spoken_style": {"score": 4, "reason": "..."},
  "length":       {"score": 3, "reason": "..."},
  "followup":     {"score": null, "reason": "单轮题，N/A"},
  "overall": 4.1,
  "pass": true,
  "summary": "..."
}
```

## 写法原则

- 每个分档写**可观察的行为**，不要写“优秀 / 良好”这种空话。
- 维度不超过 5 个，太多会带来噪声和打分负担。
- 权重体现优先级：**事实性 > 相关性 > 风格 / 长度**。
- 校准：先人工标 10–20 条，再让 LLM 裁判按本 rubric 打分，对比一致率后微调。
